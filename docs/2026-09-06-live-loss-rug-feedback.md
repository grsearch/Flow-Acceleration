# 实盘 50% 大亏反馈闭环

## 目的与边界

`LEGACY-EARLY-FLOW-RUGX` 继续使用此前授权的 0.02 SOL、并发 3、每笔优先费 0.0001 SOL。此修改不增加仓位、不取消止损，也不直接部署服务。新增的研究闭环默认启用，可用 `FLOW_LIVE_LOSS_RUG_FEEDBACK_ENABLED=false` 停止新反馈；不影响正常卖出。

亏损达到 50% 是建立案例的条件，不是认定 RUG 的充分证据。只有 LIVE 仓位参与；DRY_RUN / Shadow 不会伪装成真实亏损样本。

## 证据与结算

1. 提交买单前固定本地已观测到的入场前证据、信号身份、参考价、池储备和生命周期。缺少历史就保留未知，不能用未来数据补造当时的持仓结构。
2. 通过实盘行情准入的报价首次跌至入场价的 50% 时，预采暴跌前后证据。旧行情、乱序、无效 POST 池状态不能触发该路径。浮亏不是已结算亏损。
3. 仓位关闭且所有相关链上订单的 SOL 收支结算完成后，按实际净收益再次判断是否达到 -50%。同时接即时结算、延迟回执补齐和重启后的分页补处理。
4. 入场证据与首次触发证据不可覆盖；后续确认信息另存。按仓位 ID 去重，后台故障重试，历史缺证据不自动标毒。

独立低价确认尚未到达时，最多额外等待 5 秒；等待状态先保存，可重启恢复。超时仍不足则保留候选，不等待无限久，也不强行升级过滤。曾触发浮亏但最终结算未达 50% 的案例撤销大亏资格；未成功入场的记录不计大亏。

记录的真实净亏包括手续费和失败交易成本，不等同于代币价格跌幅；数据库 `exit_price` 也不能直接代替真实链上卖出价。归因必须把交易回执与公开行情一起看。

## 自动学习规则

所有大亏都进入案例统计，但不是所有案例都进入硬过滤：

- 高置信暴跌模板：要求可信、同市场同生命周期的模板及暴跌证据，后续独立行情确认；通过检查后保存学习记录并更新本地过滤缓存。
- 普通下跌、执行问题、混合原因、弱模式或缺证据：分别标记，保留为复盘或候选，不自动生成宽泛拦截条件。
- 本轮新的亏损反馈路径只自动学习高置信模板，不凭一笔亏损自动拉黑钱包；相关地址和行为角色保留在证据中。既有毒钱包学习规则不变。

新模板从实际识别并持久化的时点起对后续事件生效，不能反向改写当时的过滤结果。识别到新模式不等于它已具备可泛化的预测能力。一次未知 RUG 也不能保证下一次不会换地址或换手法。

## 性能与验收

交易链路不扫描历史数据库、不回填钱包、不新增 RPC；只读取有界内存并排队。持久化及案例处理按小批进行，重启补处理走专用索引与游标。内存/证据不完整、数据库保存失败应显式可见，不能算作“没有大亏”或“已成功学习”。安全停止若仍有未保存证据会报告失败并允许重试，不强制退出。

学习证据最多为 64 个币保留每币 60 秒／256 笔滚动事件，冻结的入场快照另存。后台案例每批最多处理 10 个，恢复默认每页 25 个候选 ID（先分页再筛选，即使全是已完成记录也推进游标）。新增写入的锁等待预算为 25ms，忙时留队列重试并恢复原连接设置，不增加全局 SQLite 超时。

Dashboard 在实盘策略详情显示大亏反馈统计与案例；即时运行状态在 `liveTrading.lossRugFeedback`。案例数量、确认 RUG 数及模板学习数不能替代后续收益验证。实际过滤效果继续看 BASE / RUGX 同源对照中的拦截、被拦赢家和尾部损失，样本不足不能宣称有效。

每日/手动窗口导出包含案例及相关仓位、订单。冻结快照保留原时点；案例后续归因是导出时状态，不宣称历史窗口当时已经知道未来结算或学习结果。

本地端到端验证使用真实 Tracker、ResearchStore 和 LiveTradingManager，链上执行及回执为离线模拟：57.75% 的可信暴跌（低于原自动学习器 60% 门槛）造成超过 50% 的结算亏损，反馈生成一条模板，随后同阶段另一币的匹配模板被在线过滤；重复结算不重复学习。该验证不连接生产、不签名、不代表已经验证策略盈利。
