# Legacy Early Flow RUGX 0.02 SOL

本次修改按用户明确授权，在部署时关闭其他实盘的新开仓，仅允许 `legacy_early_flow_rugx_live`（页面编号 `LEGACY-EARLY-FLOW-RUGX`）入场。源码修改不等于已经更新生产服务；必须通过安全更新流程部署和验证。不要用手动启动、强杀和另起实例替代现有服务管理。

## 固定版本

- 来源：dump-sniper-volume 的 EARLY_FLOW 入场，历史实现 86ac1bd。
- 本版本 `LEGACY_EARLY_FLOW_EXEC_V1` 是旧入场加当前执行保护，不宣称完全复刻旧版收益或多个历史卖出版本。
- 单笔 0.02 SOL，总并发及本策略并发都是 3 仓，每 mint 每版本最多一次成功开仓。
- 普通及紧急退出优先费均为每笔交易 0.0001 SOL。不设累计金额、累计亏损或累计交易次数封顶。
- 硬止损 30%，盈利 10% 激活移动止盈，从高点回撤 5% 退出，最长持仓 30 分钟。止损是触发条件，不保证实际成交亏损不超过 30%。
- 保留紧急开关、未解决的执行异常拦新仓、余额与行情真实性保护。所有旧持仓继续按其保存的策略退出，未删除旧定义或历史数据。

## 入场与低频参考价

迁移后 15–25 秒，FDV 15,000–100,000 USD，最近 10 秒价格变化 -10% 至 +8%，最近 1 秒净流入 >0，最近 5 秒至少 3 个买入地址、4 笔交易，最大单笔买入占这段买入总额 ≤70%。不依赖 Smart Wallet 共振。

保留旧版价格窗口的回退行为：不足 10 秒历史时，使用已收到的最早有效行情作基准，并单独记录实际覆盖时长及 `priceWindowComplete=false`，不冒充完整 10 秒。迁移时间必须有明确迁移或毕业事件证据，不能拿第一笔 AMM 成交时间替代。

FDV 使用已收集的代币总量、有效 POST 池价和统一缓存的 SOL/USD 参考价。参考价来自公开 Coinbase spot 接口，每分钟异步刷新一次，有效期最多 5 分钟。只用于美元换算，不是代币执行报价。不在每次买入前扫描钱包、调用价格 API 或新增 Helius 请求。缺失或过期时拒绝新信号并记录原因，既有仓位的退出不依赖该参考价。

API 依据：[Coinbase Prices](https://docs.cdp.coinbase.com/coinbase-business/track-apis/prices)。每个已产生的信号保存当时参考价格、来源及有效时间，历史回放不可使用未来参考价。

## 同源 Shadow 与实盘桥接

同一套入场下设置 `LEGACY-EARLY-FLOW-BASE` 与 `LEGACY-EARLY-FLOW-RUGX`，共用原有第二腿 Shadow 表与 Dashboard 数据接口，用独立 cohort ID 隔离统计。前者仅标记，后者按同市场、同生命周期的有毒钱包和模板硬拦。金额、成本、出口和执行延迟一致。

入场的 15–25 秒使用明确迁移时间；现有 RUG 学习器的 AMM 阶段使用首次观测 AMM 的时间，两者在数据迟到时可能不同。本版保留过滤器实际使用的阶段及年龄，另外记录入场方请求的阶段和时钟差异，不能把实际 AMM_EARLY 模板标成 AMM_MATURE。过滤与既有记忆按同一观察时钟匹配，不把正常的时钟差异额外变成拒绝条件，也不在此次改写其他策略的学习时钟。

实盘只接 RUGX 的原始合格信号，不等待 Shadow 平仓或模拟成交成功。LiveTradingManager 在实际入场前再次执行阶段匹配的 RUG 检查。过滤器不可用时明确拒绝，不能退回无过滤实盘。

Shadow 采用严格 POST 储备执行，入场/退出都以触发时刻加 1 秒作为执行目标，只接受目标之后的后续新行情。缺报价不伪造成交，不用旧缓存平仓，也不直接记为 -100%。这些延迟是可审计的模拟假设，实盘仍需逐笔对账。

## 历史毒记忆

毒钱包/模板只允许在 labeled_at 和写入时间 created_at 都到达后生效。窗口导出保留窗前已知、窗内仍有效的长期记忆以及窗内新增记录；剔除结束后才识别或才写入的记录。旧 JSON 缺少 createdAt 时仅兼容其有效 labeledAt，不能据此宣称已经验证旧历史数据的完整因果时序。冻结 cursor、执行版本和出口存入 Shadow features_json，重启恢复不重新解释历史持仓。

## 部署验收

1. 使用既有安全更新流程，确认没有其他写库实例，源文件与提交完整性匹配。不要自动删库、强杀进程或强制覆盖脏文件。
2. `/api/strategy-status` 只有 `legacy_early_flow_rugx_live` 的 `entryEnabled=true`，金额为 0.02；全局 LIVE、签名配置、余额与紧急开关仍决定实际执行能力。
3. `/api/health` 的配置完整性无校准桥接/费用警告；迁移流、AMM 流及 SOL/USD 缓存就绪。Dashboard 显示两个新的 Shadow 项以及独立实盘源诊断。
4. 一旦出现合格事件，核对同 episode 的 BASE、RUGX；源头已被 RUGX 拦截的事件记录 NO_ENTRY 和具体原因，不发实盘信号。放行事件再核对 Live decision，区分源头过滤与实盘执行拒绝。RUGX 零拦截不能宣称过滤有效。
5. 比较已结算净收益、尾部损失、被拦截的赢家/亏单、费用与信号到成交延迟，不只看胜率。

新开仓单独开关为 `FLOW_LIVE_LEGACY_EARLY_FLOW_RUGX_ENTRY_ENABLED`，默认 true；设为 false 只停止新仓。旧 `FLOW_LIVE_EBA_CAL02_ENTRY_ENABLED` 不再重新启用 CAL02。

## 本地验证

本次 102 个回归脚本全部通过，包含真实 Suite → LiveTradingManager 的 DRY_RUN 联调、真实内存数据库的两组配对、独立 Dashboard 子进程、重启去重、移动止盈高点恢复、SQLite 写入故障隔离和历史标签时间边界。测试不连接生产、不签名、不下单；不代表新策略已经盈利或已在服务器启用。

Shadow 状态无法保存时标为 DATA_ERROR 并排除出可比收益；持续无法保存时停止流程报明确错误，不宣称安全停止。重启时已经错过入场执行目标的待入场记录记为未知，不能用后到的有利行情补造入场。
